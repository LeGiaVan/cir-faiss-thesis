FAISS Trade-off: Recall Retention vs Speedup

Each point is one FAISS configuration (nlist/nprobe/M/efSearch/m). X axis = speedup over brute force (FlatIP, log scale). Y axis = Recall Retention@10 (% overlap with FlatIP's own top-10, independent of ground truth). Dashed line = the 95% reference threshold. Gray star = FlatIP (the exact baseline, speedup = 1×, retention = 100%). Repeated measurement: Latency/QPS are averaged over 7 search trials per index; HNSWFlat is additionally rebuilt independently 5 times (3 search trials each), since it's the only index type with genuine construction randomness (random level assignment) — its points show a vertical error bar for the resulting std across builds. IVFFlat/IVFPQ/FlatIP were empirically verified deterministic across rebuilds (fixed k-means seed), so a single build suffices for them.

IVFFlat (n=1, deterministic) HNSWFlat (n=5 builds, mean±std) IVFPQ (n=1, deterministic) ★ FlatIP (exact brute-force baseline)

The X axis shares the same log scale across every panel, so speedup gains can be compared directly across datasets of very different scale (CIRR/FashionIQ ~2–6K images vs.\ CIRCO 123K images).
